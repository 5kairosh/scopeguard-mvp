# ScopeGuard

IT жобаларындағы қосымша талаптарды бағалау және клиентпен келісуге арналған MVP.

**Қазақша · Русский · English**

Сайт: https://5kairosh.github.io/scopeguard-mvp/

## Мүмкіндіктер

- Логин және құпиясөз арқылы аккаунтқа кіру. Email қажет емес.
- Supabase ортақ дерекқоры: менеджер мен клиент бір жобаны бөлек аккаунттардан көреді.
- Бастапқы талаптар, бюджет, дедлайн және өзгеріс сұраулары.
- Әр өзгеріске 1–3 шешім нұсқасы: сағат, тариф, қосымша күн.
- Клиент түзету сұрай алады; әр жаңа бағалау бөлек нұсқа ретінде сақталады.
- Клиент бір ұсынысты мақұлдайды немесе өзгерісті қабылдамайды.
- Бюджет пен дедлайнға тек мақұлданған нұсқа қосылады.
- Автоматты жаңарту (Supabase Realtime және 15 секунд сайын қосымша салыстыру).
- Оқылды/оқылмады белгісі бар жеке хабарландырулар; жабық сайттағы оқиғалар да сақталады.
- Email-сіз, бір реттік құпия кодпен құпиясөзді қалпына келтіру.
- Сервердегі рұқсат тексерулері және ескірген нұсқаны өзгертуден қорғау.
- Шешімдер тарихы, JSON экспорты, үш тіл, телефонға бейімделген интерфейс.

## Ортақ жобаны тексеру

1. Менеджер мен клиент жеке логинмен тіркеледі (3–32 латын таңбасы, сан, `_ . -`; құпиясөз 10–128 таңба).
2. Менеджер жоба құрып, клиенттің логинін енгізеді.
3. Өзгеріс сұрауын тіркеп, менеджер бірнеше бағалау нұсқасын жібереді.
4. Клиент автоматты келген ұсынысты қарайды; түзету сұрайды немесе бір нұсқаны мақұлдайды.
5. Басқа аккаунттағы өзгерістер автоматты келеді. Байланыс үзілсе, қосылғанда қайта салыстырылады. «Жаңарту» қолмен жаңартуға да қолжетімді.

Мысал: бастапқы бюджет 500 000 ₸, дедлайн 2026-11-01. Клиент 10 сағат × 5 000 ₸, +2 күн нұсқасын мақұлдаса, бюджет 550 000 ₸, дедлайн 2026-11-03 болады.

Аккаунтқа кірмей демо режимін пайдалануға болады. Демо деректері браузерде бөлек сақталады және ортақ дерекқорға автоматты көшірілмейді. Ортақ режимде рөл сервердегі жоба иесі мен тағайындалған клиентке байланысты анықталады.

## Жергілікті іске қосу және тесттер

Статикалық HTTP серверін осы каталогта 4187 портында іске қосыңыз. Frontend құрастыруды қажет етпейді; аккаунттар үшін интернет және `config.js` ішіндегі Supabase қосылымы қажет.

```sh
npm ci --ignore-scripts
npm test
```

Тесттер модельді, үш тілдегі сөздіктерді және PGlite арқылы нақты PostgreSQL рұқсаттарын, нұсқалар қақтығысын, түзету тарихын, таңдалған ұсыныстың мақұлдануын, тіркелу шектеулерін тексереді.

## Supabase серверін орналастыру

`supabase/migrations/` миграцияларын ретімен қолданыңыз. `supabase/functions/register/index.ts` және `supabase/functions/account-recovery/index.ts` функцияларын `register` және `account-recovery` атымен, JWT тексеруі қосулы күйде орналастырыңыз. Қазіргі жоба: `wroykwsokjybkxkncirk`.

`config.js` тек жоба URL-ін және браузерге арналған public anon кілтін қамтиды. `service_role` кілтін frontend-ке, GitHub-қа немесе config.js-ке қоспаңыз. Тіркелу функциясы әкімшілік кілтті тек Supabase серверінің ортасынан алады.

Логиндер Auth жүйесінде `username@accounts.scopeguard.invalid` ішкі идентификаторымен сақталады; бұл нақты email мекенжайының иелігін білдірмейді. Функция email жібермейді. Тіркелу күніне бір IP хэшіне 10, жалпы 100 әрекетпен шектелген. Production доменін өзгерткенде функциядағы рұқсат етілген origin тізімін жаңартыңыз.

## Құпиясөзді қалпына келтіру

Жаңа аккаунт ашқаннан кейін құпия қалпына келтіру коды бір рет көрсетіледі. Бұрын тіркелген пайдаланушы «Аккаунт қауіпсіздігі» бөлімінде қазіргі құпиясөзімен код жасайды. Кодты қауіпсіз жерде сақтау керек; ол localStorage-қа және жоба экспортына жазылмайды. Дерекқорда тек SHA-256 хэші сақталады (кодта 256 бит кездейсоқтық бар).

«Кіру» → «Құпиясөзді ұмыттыңыз ба?» арқылы логин, код және жаңа құпиясөз енгізіледі. Сәтті қалпына келтіргенде код жаңарады; ескі код қайталанып қолданылмайды. Генерация қазіргі құпиясөзді және серверде тексерілген сессияны талап етеді. Қате аккаунт/код бірдей жауап алады; әрекеттер IP хэші, аккаунт және жалпы күндік шектермен шектеледі. Аккаунтқа кіру мүмкіндігі де, алдын ала сақталған код та болмаса, өздігінен қалпына келтіру мүмкін емес.

Supabase Auth арқылы глобалды шығу refresh-сессияларды жояды. Бұрын берілген access JWT мерзімі біткенше жарамды болуы мүмкін: бұл MVP әр сұрауда auth.sessions тексеруін қолданбайды. Қалпына келтіру server admin API-лерін пайдаланады; құпия әкімшілік кілт браузерге берілмейді.

## Дерекқор тексеруі

Advisors-та recovery және rate-limit кестелеріндегі RLS/no-policy — әдейі толық жабық кестелер. Қоғамдық RPC-лердің SECURITY DEFINER белгісі — рөл мен мүшелікті тексеретін бұрынғы жазу API-і. Тесттер рұқсатсыз оқу/жазудың бұғатталуын тексереді. Жоба баптауындағы leaked-password protection әлі өшірулі: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection

## GitHub Pages және MVP шектеулері

Pages: `Deploy from a branch`, `main`, `/(root)`. Өзгерістер main тармағына push жасалғанда жарияланады.

Хабарландырулар сайт ішінде көрсетіледі; email, браузер push және Telegram арналары қосылмаған. Тізім соңғы 100 хабарландыруды көрсетеді. Форма толтырылып жатқанда басқа өзгеріс келсе, мәтін сақталып, соңғы нұсқаны ашу туралы ескерту шығады. Қосымша күндер календарлық күндер ретінде қосылады; қатар орындалатын жұмыстар мен демалыс күндері жеке есептелмейді. Пайдаланушы мәтіндері автоматты аударылмайды.
